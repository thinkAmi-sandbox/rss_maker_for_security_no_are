# セキュリティのアレ 過去回アーカイブフィード生成ツール
## はじめに

これは非公式のツールです。番組・公式サイトとは一切関係ありません。


## ツールを作った背景

ポッドキャスト「[セキュリティのアレ](https://www.tsujileaks.com/)」の公式RSSフィードは、最新300件の配信となっています（2026/08/13現在）。

そのため、最新300件に含まれない過去回はRSSフィードから取得できず、各種ポッドキャストプレイヤーでは再生できません。

一方、音源ファイル自体は公式サーバーにあります。

どうしてもポッドキャストプレイヤーで聴きたかったため、「ポッドキャストプレイヤーへ登録できるよう、不足している過去回のRSSを生成する」ツールを作ることにしました。



## 機能について

このツールは、「現在配信されていない回だけ」を集めた標準 RSS 2.0 のアーカイブフィード(`archive.xml`)を生成します。

番組を新しく聴き始める人が、取りこぼした過去回を自分のポッドキャストプレイヤーに取り込むための、この番組専用の使い捨てフィード生成ツールです。

そのため、以下の機能はあえて実装していません。

- すべての回のフィード
   - RSSを生成するのは、現在配信されていない差分のみです
- 音源の再ホスト
   - 音源はすべて公式サーバーのものを利用します


## 生成されるフィードの元データについて

[セキュリティのアレまとめ](https://are.bocchi-megane.dev/) 様が公開いただいている、全放送回のリスト（CSVファイル）が元データです。作成・公開していただき、ありがとうございます。  
[BerandaMegane/Security-no-ARE-words: セキュリティのアレまとめ](https://github.com/BerandaMegane/Security-no-ARE-words)

この全放送回のリストを利用し、実行時点の「不足している過去回」を特定しています。


## 生成されるフィードについて

標準的なRSS 2.0の要素に加えて、各itemには出典宣言として、RSS 2.0の標準要素である `<source>` が入ります。

```xml
<source url="https://www.tsujileaks.com/?feed=podcast">セキュリティのアレ</source>
```

`url` 属性には、このツールが差分の計算に使った公式フィードのURL(`--feed-url` を指定した場合はその値)がそのまま入ります。

これは「このitemがどのフィード由来か」の情報で、ポッドキャストプレイヤーでは無視されるか、出典として表示されるだけです。


## 使い方
### 環境

Pythonのインストールが必要です。内部では `xml.etree.ElementTree.indent` を使っているため、Python3.9以降が必要です。

なお、開発・動作確認時のPythonバージョンは `mise.toml` ファイルを確認してください。

### 1. RSSのもととなるXMLファイルの生成

次のように実行することで、セキュリティのアレまとめ様のリポジトリのmainブランチから放送回データが自動的にダウンロードされます。デフォルトではメモリ上へのダウンロードのみで、実ファイルとしては保存しません。

```
# リポジトリのルートディレクトリで実行する
python -m src.cli
```

### 2. 実行サマリと archive.xml を目視確認

実行したディレクトリにファイルができるため、壊れていないことを目視確認します。


### 3. https で配信できる場所(Gist / GitHub Pages など)に一時的に配置

このツールにはRSSや音源の配信機能がないため、GitHub Gistなどで一時的に配置します。

GitHub Gistの場合、secret gistとして、 `archive.xml` のファイルの中身をコピペし、 任意の名前のXMLファイルとして保存すればよいです。


### 4. プレイヤーで取り込む

ご利用のポッドキャストプレイヤーでRSSを使って取り込みます。

ただし、一般的なポッドキャストプレイヤーでは、既存の購読とは自動で統合されず別番組として登録されます。

## 注意事項

- シーズン2(2015〜2017、@IT 時代)は、RSSの配信対象外です
   - この時期は @IT の動画連載であり、音声ポッドキャストのアーカイブである本ツールの対象外というポリシーです。視聴したい場合は [@IT の連載インデックス](https://atmarkit.itmedia.co.jp/ait/series/2517/index.html)から、多くの記事でYouTube埋め込みをたどれます
- リンク切れを検出した回は、タイトルに `【音源リンク切れ】` の接頭辞を付け、詳細を description に記録した上で、enclosure は残します(存在の記録のため)
- エピソードの同一性を担保する `guid` は以下のロジックで決めています
   - 観測台帳([data/guid_ledger.csv](data/guid_ledger.csv))にその回の記録があれば、公式フィードで実際に配信されていた guid をそのまま使います。台帳は生成のたびに自動で追記されます
      - リポジトリにあるのは、2026/08/13 に初回実行したものです
   - 台帳にない回(台帳開始前に押し出された回)は `http://www.tsujileaks.com/?p=記事番号` として作成します
   - 過去回について公式フィードでの配信が始まった場合、本ツールの `guid` とは異なる可能性があります
      - この場合、このツールで取り込んだものについては二重登録されますが、ご了承ください
- セキュリティのアレまとめ様のリポジトリの構成変更などで動作しなくなる可能性があります
   - 先方へ問い合わせず、本リポジトリのIssueへの投稿をお願いします
- 生成したフィードは個人利用の範囲に留め、公開の場で配布しないでください
   - 公式サーバーへの負荷が高まったり、意図しない再配布になる可能性があります
