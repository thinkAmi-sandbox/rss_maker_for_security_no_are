# Spec Delta: archive-feed-generation

## ADDED Requirements

### Requirement: ファン CSV の取得と入力検証

ツールは既定で、ファンリポジトリの自動更新 CSV を GitHub から直接取得しなければならない(MUST)。取得は2段で行う: まず GitHub API で main ブランチの最新コミット sha を確定し、次に**その sha に固定した** raw URL から CSV をダウンロードする(記録するハッシュと取得内容の食い違いを構造的に防ぐため)。取得した CSV はメモリ上で処理し、ファイルとして保存しない。利用者は git を必要としない。

`--csv` でローカルファイルのパスが明示された場合は、リモート取得の代わりにそれを読み込まなければならない(MUST)(開発・オフライン再現・ファンリポジトリ消滅時のバックアップ用)。

いずれのモードでも、列へのアクセスは必ずヘッダ名で行い(列順に依存しない)、必須列(`season`, `num`, `title`, `published_datetime`, `url`, `audio_url`)の存在を検証し、欠けていれば即座に異常終了しなければならない(MUST)。`recorded_date` 列は値の信頼性がないため(ダミー値と実日付の混在)、いかなる目的にも使用してはならない(MUST NOT)。

#### Scenario: リモート取得(既定)

- **WHEN** `--csv` を指定せずに実行する
- **THEN** main の最新コミット sha が確定され、その sha に固定した raw URL から CSV がダウンロードされ、sha が出典として記録される

#### Scenario: 正常な CSV の読み込み

- **WHEN** 必須列をすべて持つ CSV(リモート取得またはローカル指定)を処理する
- **THEN** 全行が読み込まれ、後続の処理対象選別に渡される

#### Scenario: 必須列の欠落

- **WHEN** 必須列のいずれかを欠く CSV を指定して実行する
- **THEN** 欠けている列名を明示したエラーで異常終了し、archive.xml は生成されない

### Requirement: 処理対象の選別と S2 除外の不変条件

ツールは、`url` が `https://www.tsujileaks.com/?p=<記事番号>` 形式に一致し、かつ `audio_url` が非空である行のみを処理対象としなければならない(MUST)。この条件を満たさない行は除外するが、除外されるのは `season == 2` の行(@IT 動画連載時代)のみである、という不変条件を検査しなければならない(MUST)。S2 以外の行が除外条件に合致した場合は、該当行を明示したエラーで異常終了しなければならない(MUST)。

S2 の除外は「本ツールは音声ポッドキャストのアーカイブであり、@IT がホストする動画連載は対象外」というポリシー決定である。全45記事の音源不存在を検証した事実に基づくものではない。

#### Scenario: 現行データでの選別

- **WHEN** 現行のファン CSV(S1=26行、S2=45行、S3=316行)を処理する
- **THEN** S1+S3 の342行が処理対象となり、S2 の45行が除外され、除外内訳が実行サマリに表示される

#### Scenario: S2 以外の行が除外条件に合致

- **WHEN** `season == 3` なのに `audio_url` が空の行が CSV に含まれる
- **THEN** 該当行(season, num, title)を明示したエラーで異常終了し、archive.xml は生成されない

#### Scenario: 未知の season の出現

- **WHEN** `season` が 1・2・3 のいずれでもない行が CSV に含まれる
- **THEN** 黙って処理を続けず、該当行を明示したエラーで異常終了する

### Requirement: 現行フィードの取得と guid 形式アサーション

ツールは実行時に公式フィード(`https://www.tsujileaks.com/?feed=podcast`)を取得しなければならない(MUST)。取得したフィードの item が0件の場合、取得劣化とみなして異常終了しなければならない(MUST)。全 item の guid が正規表現 `^https?://www\.tsujileaks\.com/\?p=\d+$` に一致することを検証し、1件でも外れる guid があれば、形式ドリフトとみなして異常終了しなければならない(MUST)。

item 件数の上限・下限(現在の300件など)を機械判定に使ってはならない(MUST NOT)。フィードの保持件数は配信側の設定値であり、過去に10件→300件へ変更された実績があるため。

#### Scenario: 正常なフィードの取得

- **WHEN** 300件の item を持つフィードを取得し、全 guid が形式に一致する
- **THEN** 各 guid から p 番号が抽出され、差分計算に渡される

#### Scenario: 空フィードの検出

- **WHEN** item が0件の XML が返される
- **THEN** 異常終了し、archive.xml は生成されない

#### Scenario: guid 形式ドリフトの検出

- **WHEN** フィード内に `https://tsujileaks.com/episode/123` のような形式外の guid が1件でも含まれる
- **THEN** 該当 guid を明示したエラーで異常終了する

### Requirement: p 番号ベースの差分計算

ツールは、処理対象行の p 番号集合(CSV の `url` から抽出)と現行フィードの p 番号集合(guid から抽出)を比較し、**フィードに存在しない p 番号の回のみ**を出力対象としなければならない(MUST)。guid 文字列同士の比較で差分を決定してはならない(MUST NOT)。公式フィードの guid はスキーム(http/https)が投稿ごとに混在しており、文字列比較では誤判定が生じるため。

#### Scenario: 現行データでの差分

- **WHEN** 処理対象342回とフィード300件(第15回〜)を突き合わせる
- **THEN** 出力対象は「フィードにない p 番号」の42回(S1 の26回 + S3 の第1〜14回+雑談2本)になる

#### Scenario: フィード保持件数の変化への追従

- **WHEN** 公式フィードの保持件数が減り、これまで配信されていた回がフィードから消える
- **THEN** 消えた回は次回実行時に自然に出力対象へ加わり、エラーや警告なしで生成される

### Requirement: 音源 URL の生存確認

ツールは、出力対象の各回について `audio_url` を https スキームに書き換えた URL へ HEAD リクエストを送り、生存を確認しなければならない(MUST)。https で失敗した場合のみ、元の http URL へもフォールバックの HEAD を送り、結果を区別して記録しなければならない(MUST)。リクエストは順次実行とし、適切な間隔を空け、明示的な User-Agent を付けなければならない(MUST)。

#### Scenario: https で生存

- **WHEN** https 書き換え後の URL への HEAD が 200 を返す
- **THEN** その回はリンク切れバッジなしで出力され、レスポンスの Content-Length / Content-Type が enclosure の属性に使われる

#### Scenario: https で死亡・http で生存

- **WHEN** https への HEAD が失敗し、http へのフォールバック HEAD が 200 を返す
- **THEN** その回はリンク切れバッジ付きで出力され、description に「https では取得不可、http では取得可能」である旨と検出日時・元 URL が記録される

#### Scenario: 両スキームで死亡

- **WHEN** https と http の両方への HEAD が失敗する
- **THEN** その回はリンク切れバッジ付きで出力され、description に両スキームとも取得不可である旨と検出日時・元 URL が記録される

### Requirement: RSS 2.0 の生成

ツールは出力対象の回を標準 RSS 2.0(UTF-8)の `archive.xml` として生成しなければならない(MUST)。各 item は以下を満たさなければならない(MUST):

- `<enclosure>` を必ず持つ。`url` 属性は生存確認の結果に依存せず、常に `audio_url` を https に書き換えた URL とする(出力の冪等性のため)。`length` / `type` には生存確認で取得した実値を入れる(取得できなければ `length` は省略する)
- `<guid isPermaLink="false">` を必ず持つ(値の決定は guid-ledger 仕様に従う)
- `<pubDate>` は CSV の `published_datetime`(ISO 8601)を RFC 1123 形式に変換した値とする
- リンク切れ検出時のみ `<title>` の接頭辞に `【音源リンク切れ】` を付ける(接尾辞ではなく接頭辞。一覧表示で切り詰められないため)
- XML は文字列連結ではなく XML API で構築する(タイトル中の `&` 等のエスケープ漏れを構造的に防ぐため)

channel メタデータは、非公式であることが一目で分かるタイトル、公式サイトへの `<link>`、生成日・参照したファンリポジトリのコミットハッシュ・本リポジトリ URL を含む説明文を持たなければならない(MUST)。コミットハッシュは、リモート取得ではダウンロード時に確定した sha、ローカル指定ではその CSV を追跡している git リポジトリの HEAD とする。追跡を確認できない場合(git 管理外へのコピー等)は `unknown` を記録し、無関係なリポジトリのハッシュを出典として記録してはならない(MUST NOT)。

#### Scenario: 通常の item の生成

- **WHEN** リンク切れのない回をレンダリングする
- **THEN** enclosure(https URL・実 length・実 type)、guid、RFC 1123 の pubDate、元のままの title を持つ item が出力される

#### Scenario: 特殊文字を含むタイトル

- **WHEN** タイトルに `&` や `<` を含む回をレンダリングする
- **THEN** 出力 XML は well-formed であり、パースすると元の文字列が復元される

#### Scenario: 生成物の再現性

- **WHEN** 同じ CSV・同じフィード状態・同じ生存確認結果で2回生成する
- **THEN** 2つの archive.xml の item 集合・guid・enclosure URL は完全に一致する(生成日時などチャンネルメタの時刻情報のみ異なってよい)

### Requirement: 実行サマリの表示

ツールは実行完了時に、人間が目視確認するためのサマリを表示しなければならない(MUST)。サマリには少なくとも以下を含む: フィードの item 件数、処理対象件数、除外件数と内訳(S2)、出力対象件数とシーズン別内訳、リンク切れ件数、guid 台帳への追記件数。また、フィードに存在するが CSV に存在しない p 番号があれば、ファンリポジトリの更新停止の兆候として件数と p 番号を警告表示しなければならない(MUST)。

#### Scenario: 正常実行のサマリ

- **WHEN** 現行データで生成が完了する
- **THEN** 「フィード300件 / 処理対象342件 / 除外45件(S2)/ 出力42件(S1=26, S3=16)/ リンク切れ0件」に相当する情報が表示される

#### Scenario: ファンリポジトリの更新停止の検出

- **WHEN** フィードには存在するが CSV に存在しない p 番号が1件以上ある
- **THEN** 該当件数と p 番号が警告として表示される(エラーにはしない)
